# 母语老师终审说明

四门课（中文、英语、日语、韩语，各 A–F 六个阶段、96 个单元、720 课含读物）的目标语内容和泰语讲解都是 AI 写的，又经 AI 审校了两轮。**上架前必须请母语老师终审**，最好每门课一位懂泰语的目标语老师（泰国的中文 / 英语 / 日语 / 韩语老师）。

## 给老师的材料

1. **审校表**（推荐）：`npm run review:sheet` 生成 `content/_review/sheets/<课程>-th.csv`，每门课一个文件，约 1.35 万行，Excel 和 Google 表格都能直接打开（不提交 git，改了课以后重新生成）。按课程顺序列出：
   - 单元：泰语标题和目标、AI 口语老师的情景（英文）；
   - 每课：泰语标题和导语、读物正文、词条（目标语、读音、配音用的 `say`、泰语词义、泰文转写）、读物的理解题（✓ 是正确答案）、对话（说话人、目标语、读音、泰语译文）、讲解。
   - 最后一列 `comment` 留给老师写意见。老师只要在有问题的行写意见或改好的文字，不用碰 JSON 文件。
2. **审校备注**（本目录的 `.md` 文件，中文写的；老师不读中文时可以先用 AI 翻成泰语或英语）：
   - `<课程>.md`：全课统一的约定（拼写、读音、泰文转写、称呼等）和故事设定，以及 A–B 阶段的问题。**先看这个**。
   - `<课程>-A-part1.md` … `<课程>-F9-16.md`：每半个阶段一份。标「✅ resolved」的是 AI 审校已经决定并改好的（请抽查）；没标的是要老师拍板的问题；文末「第二轮审校」记录第二轮改了什么。
   - `<课程>-gapfill.md`：后来补进去的基础词（对话里一直在用、原来没当词条教的词）。

## 先审什么

1. A 阶段（免费，第一印象）和 `content/l1/th/ui.json`（App 界面文字）。
2. B 阶段，然后 C–F。
3. 每份备注里没标 ✅ 的问题。
4. 生成正式配音以后（`npm run audio`），听一遍多音字和专有名词；念错的词条加 `say`（见 docs/AUDIO.md）。

全部读一遍每门课大约要 40–60 小时；时间不够时，A–B 全审，C–F 先看备注里的问题再抽查。

## 怎么改回内容

开发者按老师的意见改：

- 目标语（文字、读音、对话、读物）：`content/courses/<课程>/lessons/<课号>.json`
- 泰语（词义、转写、译文、讲解、标题）：`content/l1/th/<课程>/lessons/<课号>.json`
- 单元标题、AI 老师情景：`content/l1/th/<课程>/course.json`、`content/courses/<课程>/course.json`

课号和词条 id（表里的 `lesson`、`id` 列）**永远不改**。改完跑 `npm run validate -- --target <课程>` 和 `npm run dupes -- --target <课程> --meanings`，把老师的决定记进对应的备注（标 ✅），再重新生成审校表。
