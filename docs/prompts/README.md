# 用智能体写课、审校的做法和提示词

四门课的大纲、课文、读物、两轮审校、补词和 AI 老师情景检查，都是主会话（"总负责人"）派多个子智能体并行做的。这里存放这些提示词，下一个 AI 要扩充内容、开新国家或返工时可以照着用。

- `templates/`：可复用的模板（英文写的，智能体按英文提示词工作）。`{T}` 课程代码、`{LANG}` 语言名、`{UNITS}` 单元范围、`{PAT}` 课号前缀（如 `C[1-8]`）、`{NOTE}` 备注文件名（如 `C1-8`）、`{LEVEL}`、`{EXTRA}`（语言专用补充，见 `*-extra-<课程>.txt`）、`<SCRATCH>`（你自己的临时目录，放智能体的脚本）。
- `archive/`：这次实际用过的全部 116 份提示词原文，按时间排列，索引在 `archive/README.md`。

## 流水线（一门课从零到可上架前）

| 步骤 | 模板 | 一个智能体管多少 | 大约用时 |
|---|---|---|---|
| 1. 大纲：阶段、单元、每课主题、语法点、词条、AI 老师情景 | `plan-stages-CF.txt`、`plan-extend-AB.txt` | 一门课的 C–F（或 A–B） | 30–60 分钟 |
| 2. `npm run plan:apply -- <课程>-CF` 把大纲写进 course.json | — | 主会话自己做 | — |
| 3. 写课：两层（目标语 + 泰语）课文和读物，写完自查一遍 | `write-units-<课程>.txt` | 半个阶段（8 个单元，64 个文件） | 30–90 分钟 |
| 4. 审校：A–B 整体一份；C–F 每半个阶段一份 | `review-stage-AB.txt`、`review-half-stage.txt` + `*-extra-<课程>.txt` | 同上 | 40–50 分钟 |
| 5. 补词分析：对话里一直在用、却从没当词条教过的基础词 | `gap-analysis.txt` | 一门课 | 30–60 分钟 |
| 6. 补词落地（或交给还在跑的审校顺手加） | `gap-apply.txt` | 若干阶段 | 10–20 分钟 |
| 7. AI 老师情景和课文剧情对齐 | `scenario-audit.txt` | 两门课 | 20–30 分钟 |
| 8. 收尾：大纲同步、`npm run check`、`npm run e2e`、`npm run hours`、`npm run dupes` | — | 主会话 | 30–40 分钟 |

## 经验（务必看）

- **并发上限 20 个子智能体**（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 只对新会话生效）。多出来的任务先把提示词写成文件排队，有空位再派。真正的瓶颈是账号用量：碰到 429 / 用量上限时先把工作区提交成 WIP，等额度恢复后用 SendMessage 让原来的智能体接着做（它们保留上下文），不要重开。
- **分工按文件划清**：每个智能体只改自己范围内的课文件和自己的备注文件；`course.json`、`content/_plan/`、`<课程>.md` 的约定、代码只由主会话（或明确指定的一个智能体）改。智能体不跑 git、不装依赖，脚本放 `<SCRATCH>` 下。
- **输出过滤**：模型输出大段词表、拼音表、教材原文时会被过滤截断（中文最明显）。提示词里要求：词条从大纲按 id 复制、不在消息里打印长列表、一次只写一课、对话写原创的（围绕 น้ำ 和固定人物），拼音先用脚本生成草稿再手改多音字。审校被截断时让它"小步做"后继续。
- **故事一致性靠"后面服从前面"**：审校只改自己的单元去配合更早的阶段；发现更早的阶段自相矛盾时不自己挑，报告给主会话决定，再把决定发给相关的智能体（见各 `content/_review/<课程>-*.md` 的「第二轮审校」）。
- **约定先定再推**：拼写、读音、泰文转写、称呼等约定写进 `content/_review/<课程>.md` 的「约定」，审校按它统一；主会话中途定的新约定要用 SendMessage 发给正在跑的同语种审校。
- 每个智能体完成后主会话要做：`npm run validate -- --target <课程>`、看报告里的"范围外的问题"、提交。
- 最终报告要求简短（改了几课、最重要的 10 处、定下的约定、范围外需要改的 id、更早阶段的矛盾、留给母语老师的问题数）。
