> 最后更新：2026-10-23。先读本文件，再读根目录的 `CLAUDE.md`（仓库结构、命令、约定），路线图见 `docs/ROADMAP.md`。

## 1. 这是什么

**LinguaSEA**（开发代号，品牌名待用户定）：给东南亚人学中文 / 英语 / 日语 / 韩语的订阅制 App，iOS、安卓、网页一套代码（Expo）。第一个市场是泰国（泰语讲解）；内容分两层，开新国家只翻译讲解层。产品方案见 `docs/PLAN.md`。

参考对象是用户给的 https://github.com/smallyjh-boop/taihaoshuo ，目标是做得比它好。

## 2. 用户（店主）的要求和工作方式

- 用户说中文，**回复一律用中文**。
- 主会话是"总负责人"：除了必须用户本人做的事，其他技术、产品、内容决定都自己做，不用问（"只要对课程有利，你不用问我，直接一口气做完"；"一次性开发完，不用问我，做好你再复盘测试哪里要改的直接修改"）。
- **只有用户本人做**：品牌名定稿、开发者账号和付款主体、所有密钥和商店后台、价格定稿、上架发布、请母语老师和律师。密钥一律不进仓库，由用户填进云端环境变量（变量名见 `docs/LAUNCH.md` 和 `server/.env.example`）。
- 内容目标：每门课 A–F 学习时长 ≥ 200 小时（`npm run hours`，口径见 docs/CONTENT.md §6）。

- 每次结束前把改动提交并推送到工作分支（当前是 `claude/repo-reference-0uxm8x`）。
- 完成后要把所有信息、提示词、路线图放进仓库，方便交接（就是本文件、`docs/ROADMAP.md`、`docs/prompts/`）。

## 5. 已知问题 / 技术债

- 课程内容是 AI 写的；审校备注里没标 ✅ 的问题要母语老师拍板。四门课的泰文转写有几处"看着像不雅泰语词"的待定（韩语 꾸- กู…、외롭다 เวรบตา、새롭다 แซรบตา 等，见各备注）。
- 配音还没生成，现在用设备自带 TTS。对话里 `b` 一律男声、`c` 女声，但英语的 Emma、日语的 ゆき 这类女性角色有时用 `b`：要按角色配声音，得先在内容格式里区分说话人（docs/AUDIO.md）。
- 日语"汉字只用教过的词"：E 阶段 変わる 写汉字（E9-06 讲解里教过），F 阶段多数写かな，母语老师可统一。
- 中文、日语、韩语里有 7 个词条的课没有把 `minutes` 加 1（英语加了），对总时长影响很小。
- 日语 さん（先生/小姐）和 さん（三）是两个词，已在 `content/courses/ja/course.json` 的 `homonyms` 声明。
- 还有一些基础词课文在用、但从没当词条教过（补词时没进清单或课已满 7 个词条）：韩语 지나가다、언제든지、적다、국기 等（`content/_review/ko-F1-8.md`、`ko-E9-16.md`），日语 うる（F5-r01）。以后可以在首次出现的课补词条或改说法。
- 韩语 D15-r02 南在釜山住周五、周六两晚，和"每周六打工"的设定有点冲突；원룸 读 wonrum 还是 wollum 待母语老师定。
- AI 老师（`server/src/tutor.ts`）允许情景需要时聊朋友、恋人这类日常话题（日语 D14、韩语 D3、E3 的情景用到），但不许调情和色情内容。
- 法律页面和 `app/src/lib/config.ts` 里的 `[TBD]` / `[รอกรอก]`、support@example.com 要换成真实信息。
- 品牌名 LinguaSEA 只是代号（`app/app.json` 一处可改），上线前要查商标。

## 6. 用户说"跑配音"时

前提：用户已在云端环境设置里加了 `AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`（`southeastasia`），并在 Network access 的 Allowed domains 里放行 `southeastasia.tts.speech.microsoft.com`（新会话才生效）。不需要服务器已部署。

1. `curl -sS -o /dev/null -w '%{http_code}' https://southeastasia.tts.speech.microsoft.com/` 确认能连上；连不上就请用户按上面放行域名。
2. 用户决定**先用 Azure 免费层（F0）测试通过再付费**：先跑 `npm run audio -- --stage A --stage B --dry-run` 看计费字符（约 33 万，在每月 50 万免费额度内），再去掉 `--dry-run` 生成；以后每月一个阶段，或用户改成付费层后一次跑完（全部约 39,400 段、约 US$35）。中途断了直接重跑，已生成的跳过。分阶段的做法见 docs/AUDIO.md「先用免费层」。
3. 决定（已定）：mp3 和 `manifest.json` 都提交进 git（`content/audio/<课程>/`，约 400–600 MB），分几次按课程提交、推送，避免一次推送过大。
4. `npm run content` 把配音编进 App 内容包，`npm run e2e` 确认通过；抽听几段多音字和人名，念错的词条加 `say` 后重跑（只生成改动的）。

## 7. 给下一个 AI 的建议

- 先跑 `npm install`、`npm run check`；改了 App 界面用 `npm run e2e` 实际走一遍（先 `npm run content`）。
- 改课：两层文件一起改，课号和词条 id 永远不改；改完 `npm run validate -- --target <课程>`、`npm run dupes -- --target <课程> --meanings`，把决定记进 `content/_review/`。
- 母语老师返回意见后：按审校表的 `lesson` / `id` 列找到文件改，记进备注，重新 `npm run review:sheet`。
- 大批量内容工作照 `docs/prompts/README.md` 的流水线和经验来。
